# Codex 사진 수정안 — 2026-11-06

이 변경은 1번 작업인 사진·설명 → Codex 확인·질문 → 이미지·구조물 초안 → 미리보기 → 운영자 승인 흐름이다. 운영 배포는 하지 않는다. 서울역 직접 저장 잠금과 모든 역의 최초 파사드 등록은 후속 2번 작업이며 이번 변경에서 확대하지 않는다.

## 운영자가 사용하는 흐름

1. 기존 승인자 계정으로 제보를 열고 초안 전용 플러그인 연결을 완료한다. 연결 코드는 한 번만 사용하며 최종 승인 권한을 주지 않는다.
2. 사진·설명을 대화로 보내고 작업 범위에 동의한다. 서버는 제보 버전, 촬영 사진, 주변 슬롯과 허용한 독립 구조물, 최신 메시지를 고정한다.
3. `Codex에서 작업 열기`는 플러그인 언급과 최신 작업 ID가 담긴 요청문을 앱 입력창에 채운다. **운영자가 Codex에서 전송해야 시작한다.** 웹에서 저장한 것만으로 자동 실행되었다고 표시하지 않는다. 요청문 복사도 지원한다.
4. Codex는 맡긴 원본 사진과 기존 파사드 기준 이미지를 확인한다. 불충분하면 질문을 남긴다. 운영자가 답변·보완 사진을 보내면 최신 대화에 연결된 새 작업으로 이어지며 이전 초안은 승인할 수 없다.
5. Codex가 보정·생성한 이미지는 출처 사진 ID, 생성/보정 근거, 추정의 한계, 실제 출력 개인정보 검수를 기록하여 비공개 저장한다. 사진에서 관찰한 내용과 생성한 부분을 구분한다.
6. 운영자는 전후 이미지, 모든 면, 동일 정점·UV로 그린 복합 모형과 실제 3D 배치를 확인한다. 최종 승인 시에만 기존 트랜잭션 검사 후 공개 레이어에 반영된다.

## MCP 계약

기존 연결·작업 조회·대화·질문·`toolkit_submit_plan` 계약은 유지한다. 승인자 쿠키나 비밀번호를 외부 작업자에게 전달하지 않는다. MCP에는 최종 승인·공개 지도 직접 쓰기 도구가 없다.

- `toolkit_read_photo_original({job_id,photo_id})`: 해당 작업 원본과 SHA256, 촬영 면, 크기를 반환한다. 다른 제보·미전송 첨부는 읽지 못한다. 원본은 기존 제보 한도인 긴 변 2048px 이하다.
- `toolkit_read_facade_reference({job_id,alias})`: 허용된 주변 슬롯의 승인/등록 기준 이미지를 최대 640px로 반환한다. 기준 이미지가 없거나 접근할 수 없으면 그 사실을 알린다. 임의 URL을 받지 않는다. 직접 보지 못한 기준 이미지를 확인했다고 주장하지 않는다.
- `toolkit_store_draft_artifact({job_id,request_id,source_photo_ids,image,provenance})`: `image`는 PNG/JPEG data URL이다. `provenance`는 `{method:'generated'|'rectified',evidence,uncertainty,privacy_reviewed:true}`이며 근거와 한계는 각각 1~1000자다. 실제 사진을 원본 출처로 지정해야 한다. 반환값은 `artifact_id`, `sha256`, `px`, 출처와 검수 정보이며 이미지 본문을 포함하지 않는다.
- `toolkit_submit_plan`: 기존 사진 사영용 면 `{side,photo_id,quad,privacy_reviewed,people}`와 새 면 `{side,artifact_id}`를 함께 쓸 수 있다. 저장한 이미지의 크기가 기존 슬롯 또는 구조물 면 규격과 정확히 일치해야 한다. 다른 작업의 이미지는 사용할 수 없다.

새 이미지 본문은 최대 4.8MB, 한 변 4096px, 총 4,194,304픽셀이다. 2146×733 파사드를 지원하며 4096×4096은 거부한다. 이 업로드 도구에만 최대 7MB JSON 본문을 허용하고 나머지 MCP 요청은 70KB를 유지한다. 서버는 실제 디코딩 후 PNG로 다시 인코딩하여 부가 메타데이터를 제거한다. JPEG 디코더 메모리 한도는 48MB다. 이미지 업로드 본문이나 base64를 대화·로그에 펼치지 않는다.

`job_artifacts`와 비공개 R2 객체에 작업·승인자·제보 버전·원본 사진·해시·검수 정보를 저장한다. 저장 직전에 연결 만료/철회와 최신 대화를 다시 확인한다. 동시 재전송은 고유 R2 키를 사용하여 패자가 승자의 이미지를 삭제하지 않는다. 생성 결과는 공개 승인 전까지 공개 이미지 API로 열리지 않는다.

## 복합 구조물

기존 `structure` 필드를 유지하면서 선택적으로 `parts` 1~32개를 받는다. 로컬 좌표는 미터이며 x는 오른쪽, y는 뒤쪽, z는 바닥에서 위쪽이다. 모든 구성요소는 선언한 구조물 전체 `size` 범위 안에 있어야 한다.

```json
{
  "parts": [
    {"id":"body","type":"box","offset":[0,0,0],"size":[3,2,2],"color":"#eeeeee","facades":{}},
    {"id":"sign","type":"plane","vertices":[[-1.5,-1,2],[1.5,-1,2],[1.5,-1,2.5],[-1.5,-1,2.5]],"texture":"front","uv":[[0,0],[1,0],[1,0.2],[0,0.2]]}
  ]
}
```

평면은 비퇴화·볼록·동일 평면 사각형이어야 한다. UV는 0~1이며 두 렌더 삼각형의 UV 면적이 각각 0보다 커야 한다. 실제 제출한 사진 면만 텍스처로 사용할 수 있다. 사진의 본체/돌출 간판을 한 텍스처의 다른 영역에 연결할 수 있지만 실측이나 가려진 형상을 정확히 복원했다는 뜻은 아니다. 기존 parts 없는 구조물은 종전 상자 모형으로 렌더한다. 고정 모형 미리보기는 투영 기저의 깊이축(x+y+0.84z)을 사용해 상하 구성요소도 높이에 따라 정렬한다.

저장된 비공개 미리보기 이미지는 편집기에서 동일 출처로 읽어 data URL로 변환한 뒤 서울역 iframe에 전달한다. 승인자 쿠키를 다른 출처로 보내거나 비공개 이미지를 공개 API로 우회하지 않는다.

## 검증 범위

메모리 D1/R2 테스트에서 생성 이미지 출처·개인정보 검수·다른 계정/작업 차단, 동시 업로드·충돌, 비공개 초안, parts 보존과 사람의 최종 승인, 기존 질문·최신 대화·철회/만료를 확인한다. 실제 생성형 모델의 품질과 운영 배포는 별도다. 새 포트·전역 서비스·패키지 설치 없이 기존 런타임을 사용한다. Codex 자동 실행 runner는 별도 문서의 명시적 실행 계약을 따른다.

로컬 복합 구조물 시각 검증은 `node tools/seed-codex-preview-structure.mjs --credentials PATH`로 별도 시험 제보를 한 번 만든다. 4197 loopback 주소와 메모리 fixture health 응답을 확인해야 실행되며 운영 호스트는 거부한다. 두 벽, 문 개구부, 상단 간판, UV 크롭과 겹친 상하 부속물을 비공개 draft로 저장하며 최종 승인은 호출하지 않는다. 비밀값과 이미지 본문을 출력하지 않고 기존 제보는 수정하지 않는다.

승인 후 대화 패널은 작업 레코드의 이전 `draft` 값보다 제보의 `applied/queued/rejected` 상태를 우선한다. 반영 완료·반영 대기·종료를 표시하고 Codex 작업 열기와 입력을 비활성화하며, 승인 결과 보기와 기존 대화는 보존한다. 실제 `mount → report → renderStatus` 경로는 `node tools/test-chat-ui.mjs`로 검사한다.
