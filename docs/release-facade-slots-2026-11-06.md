# 등록면이 없는 역의 파사드 교체

46개 연결 역에서 사진 제보를 처리한다. 서울·대전의 기존 면 목록을 유지하며, 목록이 비어 있는 다른 역은 승인자가 사진에 나온 시설의 한 면을 먼저 확인할 수 있다. 이번 변경이 44개 역의 현장 치수나 전체 3D 모델을 미리 조사했다는 뜻은 아니다.

## 승인 전 면 확인

승인자 콘솔의 파사드 변경 제보에 ‘사진을 입힐 면의 위치·규격’이 표시된다. 시설·면 이름, 제보와 같은 층, 위치, 정면 방향, 실제 폭·높이, 실측/추정 구분, 근거와 오차를 확인한다. 사진만으로 실제 치수가 정확하다고 주장하지 않는다. 사진 비교로 정한 크기는 ‘추정 · 현장 확인 필요’로 남긴다. 근거와 오차는 승인자 작업 범위에서만 읽는다.

고도는 구분해야 한다. 제보 지도 핀은 바닥을 가리킬 수 있으므로 폼에는 **면 아래끝 고도**를 입력한다. 기본값은 제보 고도이며, 바닥보다 위에 있는 간판이면 아래끝을 올려야 한다. 저장·렌더링에 쓰는 `position[2]`는 **면 중심고도 = 아래끝 고도 + 면 높이/2**다. 폼에 계산한 중심고도를 표시하고 저장된 수정안의 3D 미리보기에서 배치를 확인한다.

서버는 같은 층·제보 핀에서 12m 이내, 해당 층 근처 높이, 0.1~30m 폭·높이, 0~360도 미만 방향을 검증한다. 출력 이미지는 긴 변 1024px로 계산하거나 별도 지정한다. 한 변 32~4096px, 전체 4,194,304픽셀 이내이며 물리 폭·높이와 이미지 비율 차이는 2% 이내다. 근거 사진은 현재 제보에 속한 최대 5장만 허용한다.

등록은 **비공개 후보 저장**이다. 공개 지도 변경이나 승인 권한 부여가 아니다. 서버가 기존 면과 충돌하지 않는 별도 식별자를 만들고 승인자·제보·최신 버전에 연결한다. 등록을 다시 하면 앞선 작업·수정안은 무효화된다. 다른 승인자, 다른 제보 사진, 오래된 요청, 임의 면 식별자나 규격 변경은 허용하지 않는다.

## 사진 보정과 최종 승인

면 후보 저장 후 대화 작업을 새로 맡기면 이 승인자가 확인한 주변 면만 AI 작업의 허용 목록에 들어간다. 연결한 Codex 작업자는 원본 사진을 읽고 보정 이미지 artifact 또는 원본 네 모서리 계획을 제출한다. 면의 좌표·방향·실제 크기와 픽셀 규격은 변경할 수 없다. 면 후보만 있는 경우 기존 기준 사진이 없다고 명시한다. 사진 정보가 부족하면 추가 질문으로 이어진다. [Codex 작업자 실행과 제한](codex-draft-worker.md)을 참고한다.

사진은 지정한 픽셀 크기와 정확히 일치해야 수정안으로 저장된다. 수정안에는 실측/추정, 위치·중심고도·규격과 근거·한계를 함께 표시한다. 위치·규격·개인정보·배치와 실제 교체 대상을 사람이 확인하여 최종 승인해야 공개된다. 후보 등록자와 다른 승인자는 비공개 후보와 작업 내역을 읽거나 대신 승인할 수 없다. 일반적으로 이미 공개된 면의 사진 교체 권한은 기존 승인자 규칙을 따른다.

최종 승인 트랜잭션은 최신 제보·대화·작업·면 후보·기존 레이어 값을 다시 검증한 뒤 면 등록과 사진 레이어를 함께 반영한다. 실패 시 둘 다 되돌려지고, 중복 승인으로 이중 등록되지 않는다. 다른 승인면·시설 레이어는 유지한다. 공개 조회에는 승인된 면의 이름·층·위치·방향·폭·높이·픽셀 규격·실측/추정과 승인 이미지 주소만 추가한다. 근거·오차 원문, 원본 사진, 승인자, 비공개 후보 정보는 공개하지 않는다.

승인된 면은 다음 제보에서 그대로 재사용한다. 변경 전 비교에는 그 면의 현재 승인 이미지를 쓴다. 기존 `import-facade`로 이미 승인한 면도 저장된 면 규격을 재사용할 수 있다. 여기서 새로 등록한 면의 위치·규격은 가져오기 경로로 덮어쓰지 못한다. 수동 원근 보정 경로도 같은 비공개 면·픽셀·최종 승인 검증을 사용한다.

## 검증과 적용

- DB 변경: `0008_facade_slots.sql`과 journal/schema. 배포 시 이 마이그레이션을 적용해야 한다. 메모리 미리보기는 시작 때 마이그레이션하므로 기존 프로세스의 정상 재시작이 필요하다.
- `node tools/test-facade-slots.mjs`: 합성 사진·메모리 DB로 실제 Worker/MCP 라우트, 46개 역 descriptor의 층별 면 검증, 실측/추정, 바닥→중심 고도, 권한·사진·버전·규격 제한, 보완 질문과 후속 대화, 비공개 초안, 정확한 픽셀, 승인과 공개 조회, 중복 승인, 트랜잭션 실패 롤백, 기존 레이어 보존, 후속 교체와 수동 경로를 검증한다. 모델·외부 네트워크는 호출하지 않는다.
- 기존 reports/ai-work/dots-work/chat-work 회귀 테스트를 함께 실행한다. 운영 계정 OAuth 연결·배포·실제 역 현장 계측은 이 테스트가 확인하는 범위에 포함하지 않는다.

로컬 미리보기에서는 부산역의 가상 사진 제보를 실제 화면으로 처리했다. 승인자가 4m × 3m 면과 추정 규격을 확인해 등록한 뒤, 콘솔 대화로 작업을 맡겼다. 실제 Codex 작업자가 1024 × 768px PNG 수정안을 저장했고, 부산역 3D 화면에서 배치를 확인한 다음 화면의 최종 승인으로 공개했다. 등록한 면의 위치·중심고도·폭·높이·방향과 추정 구분이 승인 후에도 일치함을 확인했다.

같은 실행에서 승인 전 공개 조회는 면 0개·교체 이미지 0개였고 수정안 이미지 주소는 공개 접근을 거부했다. 최종 승인 후 면 1개·교체 이미지 1개가 조회되고 승인 PNG가 공개됐으며, 이미지 크기도 1024 × 768px로 일치했다. 이는 로컬 제보→면 확인→실제 Codex 수정안→3D 확인→사람의 최종 승인→공개 조회까지의 실행 검증이다. 가상 제보로 수행했으며 실제 부산역 시설의 치수나 현장 상태를 인증한 결과가 아니다. 운영 배포는 수행하지 않았다.

개인 프로젝트 저장·공유와 운영 공개 승인은 별도 경로다. 이번 면 후보 저장이나 개인 초안 저장으로 공개 지도 편집 권한이 늘어나지 않는다.
