# 개인 PC Codex 동반 작업자

편집기에서 맡긴 작업을 개인 PC가 자동 조회한다. 연결 후에는 편집기 채팅에서 지시·질문 답변·초안 확인·재작업을 이어간다. 사진 분석과 생성은 사용자의 로컬 Codex 계정으로 수행하고 최종 지도 승인은 편집기에서 사람이 한다.

## 최초 연결

1. 개인 PC에 Node와 Codex CLI를 설치하고 `codex login`으로 본인의 계정에 로그인한다.
2. Codex의 Toolkit MCP를 개인 계정으로 인증한다. 편집기 승인자 화면에서 초안 전용 연결 코드를 만들고 Toolkit의 연결 도구로 등록한다. 사이트와 MCP가 같은 서버인지 확인한다.
3. 편집기 소스 폴더에서 아래 검사를 실행한 뒤 작업자를 켠다. 작업자 코드를 실행하는 PC에는 프로젝트 의존성이 준비되어 있어야 한다.

```sh
node tools/codex-companion-runner.mjs --check
node tools/codex-companion-runner.mjs --watch
```

첫 실행 한 번은 개인 PC에서 필요하다. 이후 편집기에서 맡긴 작업·답변·재작업을 자동으로 조회한다. PC와 이 프로세스가 켜져 있을 때 작동한다. 운영체제 서비스·자동 시작 설정·새 포트를 설치하지 않는다. 종료는 해당 터미널의 Ctrl+C로 한다. 정상 종료 후 같은 명령으로 다시 켤 수 있다.

7일 접근 만료 또는 기존 연결 해제 후 **같은 승인자·같은 GPT 계정**으로 다시 인증하면 같은 작업 폴더와 명령을 사용할 수 있다. 작업자의 명시적 등록 요청에서 유효한 새 연결로 갱신한다. 이전 연결에 살아 있는 임대가 있으면 최대 90초 동안 재연결을 거부하며, 만료된 임대는 중단 이력으로 보존한다. 예전 질문·초안은 유지하고 중단 작업은 편집기에서 최신 작업 재시도로 이어간다. 다른 GPT 계정이나 승인자로 바꾸는 경우 기존 식별자를 재사용하지 않는다. 새 전용 작업 폴더로 최초 연결을 진행한다.

기본 작업 폴더 `.codex-draft-worker/`는 Git에서 제외된다. 원본 사진·생성 이미지와 작업 임대 nonce가 있으므로 비공개로 보관한다. 별도 폴더는 `--workspace /absolute/private/folder`, 한 제보로만 제한하려면 `--report REPORT_UUID`, PC 표시 이름은 `--label '개인 PC'`를 사용한다. 폴더의 제보 범위는 실행 중 임의로 넓히지 않는다. 강제 종료로 `worker.lock`이 남았다면 해당 작업자가 실제 종료됐는지 확인한 후 그 잠금 파일만 정리한다.

`--check`는 CLI 로그인·설치 MCP·초안 연결·현재 모델 카탈로그·실제 OS 파일 읽기 격리만 확인하며 모델 턴을 실행하지 않는다. `--watch`는 실제 모델 사용량을 소비한다. API 키·모델 이름을 중앙 계정으로 대체하지 않는다. 자세한 사진 처리와 OS 격리는 [기존 작업자 문서](codex-draft-worker.md)를 따른다.

## CLI 진단에 토큰이 보인 경우

표시된 값이 GitHub 개인 액세스 토큰일 수 있다면 GitHub에서 해당 토큰을 폐기한다. 연결에 계속 필요한 경우 새 토큰을 발급해 해당 GitHub 연결에 설정한다. 지원 요청에는 토큰 값 대신 오류 분류와 발생 단계를 적는다.

CLI 시작 진단은 버전과 오류 분류를 표시한다. 모델과 Toolkit 작업 오류에는 GitHub 토큰 형식, 인증 헤더와 민감 설정 값, URL 경로와 쿼리 값을 가린 뒤 필요한 오류 내용을 남긴다. 자식 프로세스에는 경로·홈·인증서 같은 런타임 환경변수를 넘긴다. 별도 MCP 테스트 연결에는 `--token-env`로 지정한 변수만 추가하며, GitHub 자격증명 형식은 거부한다. 모델 작업에 비활성 MCP 설정을 만들 때는 전송 방식만 유지한다.

## 실행과 복구

PC는 외부로만 MCP 요청을 보낸다. 서버는 연결된 승인자에게 명시적으로 맡겨진 최신 제보·최신 관리자 메시지의 대기 작업만 한 건씩 임대한다. PC의 생존 신호는 15초, 임대는 90초이며, 편집기는 마지막 응답과 오류 코드를 표시한다. 모델에는 임대 nonce를 주지 않고 호스트가 모든 초안 도구 요청을 해당 작업 임대로 감싼다.

모델 실행 직전 서버가 시작 기록을 한 번만 남긴다. 응답 유실·프로세스 재시작으로 이미 시작한 작업을 다시 발견하면 모델을 중복 실행하지 않는다. 실제 서버에 초안·질문이 있으면 그 상태를 확인하며, 실행 여부가 불확실하거나 임대가 만료됐으면 최신 작업 재시도로 이어간다. 재시도는 새 작업 ID를 만들고 이전 임대·진단 기록은 보존한다. 취소·연결 철회·다른 제보·바뀐 제보 버전·오래된 대화는 실행할 수 없다.

이미지 규격 등의 서버 검증 오류는 필요한 규격을 포함해 모델에 전달한다. 수정 가능한 입력은 같은 모델 턴에서 고쳐 다시 제출할 수 있다. 성공 표시는 모델의 말이 아니라 서버에 저장된 `draft` 또는 `needs_info`를 확인한 뒤 남긴다. 작업자 실패 자체는 지도나 승인된 초안을 바꾸지 않는다.

## 일괄 및 예약

승인자는 제보 목록 또는 역 범위를 확인하고 일괄 작업을 맡길 수 있다. 작업자 poll 한 번에 최대 3개의 비공개 대화를 준비하고 각 작업의 사진·제보 상태·기존 대화 한도를 다시 검사한다. 일괄 요청당 최대 200건이며 역 전체를 다시 요청하면 이미 예약·시도한 같은 버전을 지나 나머지 제보를 선택한다. 제보를 명시 선택한 경우 이미 진행 중인 작업은 이유를 표시하고 건너뛴다. 다른 승인자가 진행 중인 작업과 검토할 초안도 보존한다.

예약 주기는 15분~7일이며 연결된 개인 PC가 poll할 때 도래한 작업을 만든다. PC가 꺼져 있으면 실행하지 않고 다음 poll에서 한 번 이어간다. 예약 해제·일괄 취소는 아직 요청 준비를 시작하지 않은 항목을 취소한다. 이미 요청 준비 중이거나 생성된 제보별 작업은 기존 제보 화면에서 확인한다. 일괄·예약도 최종 승인 권한을 주지 않는다.

## 인증 경계와 검증

Sites에는 ChatGPT/Codex OAuth 토큰·계정 암호를 저장하지 않는다. 로컬 app-server가 사용자의 기존 Codex 로그인을 관리하며 작업자는 `auth.json`을 읽거나 복사하지 않는다. 서버에는 작업자 식별자·연결 범위·생존 신호·진단 코드와 임대 nonce의 해시만 남긴다. 인증된 로컬/오픈소스 앱과 hosted 서비스의 구분은 [공식 app-server 인증 문서](https://developers.openai.com/codex/app-server/#auth-endpoints)를 따른다. 이 경로를 hosted 모델 대행 서비스로 바꾸려면 별도 공식 인증 계약을 검토해야 한다.

```sh
node tools/test-agent-runner.mjs
node tools/test-codex-companion-runner.mjs
node tools/test-batch-work.mjs
node tools/test-codex-draft-worker.mjs
```

검사는 메모리 D1·실제 초안 채팅/임대 코드와 모의 모델을 사용한다. 임대 중복·시작 중복·다른 제보·actor 범위·만료·철회·서버 결과·질문 뒤 새 작업·프로세스 재시작·일괄 원자성·200건 이후 선택·취소 및 예약 해제 경합을 확인한다. 이 검사만으로 운영 MCP 인증이나 실제 모델 생성 성공을 주장하지 않는다. 운영 연결·실제 모델 왕복은 별도 승인된 배포 검증에서 확인한다.
